# How it works

## Chrome extension (`extension/`)

**Rules.** [`policy.js`](../extension/policy.js) is the single description of what's allowed: which URLs are destinations (posts, threads, profiles, notifications, messages, the composer, typed searches) and which are feeds. `bun run build:rules` turns it into Chrome network rules ([`rules.json`](../extension/rules.json), checked into git). Anything else on x.com, twitter.com or instagram.com redirects to the main page (`blocked.html`).

**On the pages it allows,** the content script ([`content.js`](../extension/content.js), [`content.css`](../extension/content.css)) works out which view it's on and keeps only that view's own content. Global navigation, sidebars, recommendation blocks ("Who to follow", "Discover more"), promoted posts and Instagram's Notes carousel are hidden. If it doesn't recognize a page's layout, it covers the page with a short note and a link back, rather than showing a feed by accident.

**Navigation.** Clicking a link to a feed goes back to the main page. Everything else (threads, profiles, DMs, search tabs) lets X and Instagram navigate as usual. Typing happens on the extension's page, so site shortcuts such as X's `N` can't fire.

**For You batches.** [`background.js`](../extension/background.js) opens `x.com/home` in a minimized window with a one-off, tab-scoped permission (a session network rule) to load it. [`capture-main.js`](../extension/capture-main.js) runs in the page and passes on the `HomeTimeline` response X downloads for its own For You tab. [`timeline.js`](../extension/timeline.js) parses it into tweets and sanitizes them: only `https` links, and images only from X's media hosts. The window closes, and the batch shows on [`feed.html`](../extension/feed.html), the extension's own page. A batch lasts two hours from when it's taken; until then, For You shows the same one.

**Read state.** Swiping a tweet away stores its id with the batch's start time, so a new batch starts with nothing read.

**UI.** The main page and the feed page are React with [Base UI](https://base-ui.com) components, in [`src/ui/`](../src/ui). `bun run build:ui` bundles them into `extension/popup.js` and `extension/feed-page.js` (committed, so the extension loads without a build step).

### X quirks it works around

- **Never `display:none` the page while X starts.** X computes a request signature (`x-client-transaction-id`) at start-up from a paused animation's computed `transform`, which reads `none` for an element with no layout box. Search checks that signature strictly and returns 404. So pages load with `opacity: 0`, and empty top-level elements keep their boxes.
- **Use the content script's URL, not `sender.url`.** After an in-page navigation, Chrome can still report the previous page as the sender's URL.
- **Let X handle its own navigation.** Only links into a feed are intercepted.
- **Hide recommendation blocks, not what follows them.** "Who to follow" can appear partway through a profile or search, and only that block goes.

### The unlock (hidden)

The worker can still open real X home for a 15-minute daily budget, counting only time the tab is visible and in use. The UI no longer offers it, but the code (and the `spend` sync endpoint) is kept so it can come back.

## iPhone app (`ios/`)

A SwiftUI app with a `WKWebView` browser, generated by XcodeGen from [`project.yml`](../ios/project.yml).

- **Same rules as the extension.** The app bundles the extension's `policy.js`, `content.js`, `content.css`, `timeline.js`, `capture-main.js` and the feed page, and runs them unchanged in an isolated script world. A small shim ([`Shim.swift`](../ios/Dreamscroll/Shim.swift)) stands in for `chrome.runtime`, and a hidden web view evaluates `policy.js` for navigation decisions.
- **Sessions** live in the app's own website data store, separate from Safari. [`CookieVault.swift`](../ios/Dreamscroll/CookieVault.swift) mirrors the X and Instagram cookies to a protected file, so a force-quit or reinstall doesn't sign you out.
- **For You:** [`Capture.swift`](../ios/Dreamscroll/Capture.swift) loads X home in an invisible web view to capture a batch. [`FeedStore.swift`](../ios/Dreamscroll/FeedStore.swift) is a Swift port of the extension's batch and sync logic, with the sync token in the Keychain.
- **Share extension:** "Share › Dreamscroll" from any app opens X and Instagram links here.
- **Safari blocker:** a content blocker for x.com, twitter.com and instagram.com in Safari, switched on in Settings. iOS requires turning it on once in Safari's extension settings.
- **Debug probe:** builds with the `DREAMSCROLL_PROBE` compilation condition (add `SWIFT_ACTIVE_COMPILATION_CONDITIONS = DEBUG DREAMSCROLL_PROBE` to `ios/Local.xcconfig`) run `Documents/probe.js` (copied with `xcrun devicectl device copy to …`), if present, five seconds after each page load and log the result as `SF probe`. It's for inspecting live mobile layouts and is off by default. Debug builds also allow Safari's Web Inspector; release builds don't.

Bundle IDs come from `BUNDLE_ID_PREFIX` in `ios/Local.xcconfig` ([`Config.xcconfig`](../ios/Config.xcconfig) has the defaults), and the App Group and blocker IDs are read from Info.plist, so a fork only sets those two values.

## Sync (`sync/`, optional)

The extension keeps the sync address and token in `chrome.storage.local`; the iPhone app keeps the token in the Keychain. The token is only ever sent to the server it was saved with.


One small HTTP API ([docs/sync-api.md](sync-api.md)): the first device to capture a batch in a window wins, and the server's clock decides when windows end. Both clients keep working offline with the same rules ([`feed.js`](../extension/feed.js), `FeedStore.swift`) and catch up when the server is back. [`sync/`](../sync) implements it as a Convex component.

## Manual checks after changes

Automated tests cover the rules, the parser, the worker's message handling and both pages. These need a real browser and real accounts:

- Each site's root opens the main page, and so does the toolbar icon.
- Notifications, messages, an account and an X search each show only their own content, without global navigation or sidebars.
- **Post** opens the composer centered with no feed behind it. Don't post; closing it returns to the main page.
- Instagram messages show search and the conversation list, not the Notes carousel.
- A post link opened from elsewhere loads directly, and a reply's permalink opens its thread.
- Explore, stories, the Reels feed and the logo all return to the main page.
- For You fetches a batch, swiping works, and opening a tweet then going Back returns to the same card.
